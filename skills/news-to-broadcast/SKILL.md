# 资讯转口播稿（news-to-broadcast）

本 skill 用于把「AI 情报站」（已部署的自动抓取 RSS 新闻网站）产出的当日资讯数据，按热度指标和筛选标准精选出 **top 3** 条 AI 资讯，再逐条改写成 **600 字以内** 的短视频口播稿，供真人念稿拍摄（配 PPT + 提示器）使用。

## 触发条件

当出现下列任意一种表述时，应激活本 skill：

- 「出口播稿」「写口播稿」「来份口播」
- 「选资讯做视频」「挑几条资讯拍短视频」
- 「今日资讯改视频」「把今天的 AI 新闻改成短视频文案」
- 「broadcast」「短视频文案」「口播」

## 输入

数据来自 AI 情报站的本地数据目录（相对于项目根目录）：

- `data/news/YYYY-MM-DD.json` —— 当日资讯列表，每条含 `title / desc / link / source / category / published / time`
- `data/manifest.json` —— 全量索引，含 `dates / total_items / 各日分类统计`，可用于回溯历史选题、避免重复

默认日期取「项目根目录下最新的一天」。用户也可在指令里显式指定日期，如「出口播稿，9 月 15 日的」。

## 热度指标体系（4 个维度）

对每条候选资讯按下表打分，总分 = 四维之和（满分 28）：

| 维度 | 分值范围 | 评分规则 |
| --- | --- | --- |
| ① 关键词权重分 | 1–10 | 命中下列关键词即累加，封顶 10：**模型名**（GPT、Claude、Gemini、Sora、o1、Llama、Qwen、文心、混元、豆包、RSI…）、**厂商名**（OpenAI、Anthropic、Google、Meta、Apple、字节、阿里、腾讯、百度、华为、小米、网易、Snap…）、**融资/估值**（融资、估值、亿美元、万亿、IPO、申购、拆分…）、**技术热点**（Agent、MCP、RAG、强化学习、扩散模型、机器人、GPU、芯片、算力…） |
| ② 来源权重分 | 1–5 | AI 垂直媒体 = 5（量子位、雷峰网、机器之心、36Kr AI、Ars Technica、The Verge AI、TechCrunch AI…）＞ 通用科技媒体 = 3（一般科技频道）＞ 聚合媒体 = 1（早报/要闻汇总类） |
| ③ 时效分 | +10 / +5 / +2 | 当日发布 +10；昨日 +5；前日 +2；更早 = 0 |
| ④ 话题热度分 | 1–8 | 命中下列「戏剧性元素」即累加，封顶 8：**名人**（马斯克、奥特曼、周鸿祎、周枫、罗福莉…）、**大厂**（苹果/谷歌/微软/OpenAI…）、**具体金额数字**（亿美元/万亿/烧 3 万美元…）、**直播/现场事件**（发布会/Open Day/Disrupt/ECCV…）、**冲突/反转词**（反打、反攻、翻车、难哄、沉寂后官宣…） |

> 评分优先级：① 关键词权重 > ④ 话题热度 > ② 来源权重 > ③ 时效分。同分时按此顺序决出排名。

## 筛选标准（4 条硬性标准）

打分后，必须再过 4 道硬筛，任一不过即淘汰，即使热度分高也不入选：

1. **强 AI 相关** —— 必须涉及 AI 技术 / 产品 / 公司 / 政策，纯硬件或无关行业资讯一律排除。
2. **有故事性** —— 能从标题 + 描述中提炼出 **冲突 / 反转 / 悬念 / 具体数字** 之一，避免「某公司发布公告」式流水账。
3. **可拍性** —— 画面感强、有视觉元素（人物、设备、现场、图表、数字大屏），易于用 **PPT + 口播** 呈现，避免纯抽象论文解读。
4. **信息密度** —— 单条资讯信息量足够支撑 **600 字口播**，不能太单薄（仅一句话的简讯直接淘汰）。

## 工作流程（5 步）

### Step 1：读取当日 JSON 数据

- 读取 `data/news/YYYY-MM-DD.json`，解析 `items` 列表。
- 如用户未指定日期，取 `data/manifest.json` 中 `dates[0].date`（最新一天）。
- 若文件缺失，明确告知用户「当日情报站未产出数据」，不要臆造。

### Step 2：按 4 维热度指标打分排序

- 对每条 item 计算关键词权重分、来源权重分、时效分、话题热度分，相加得总分。
- 按总分降序排序；同分按优先级（①>④>②>③）决出次序。

### Step 3：按 4 条筛选标准过滤

- 从高到低逐条评估：强 AI 相关 → 有故事性 → 可拍性 → 信息密度。
- 任意一条不过即淘汰，继续看下一条，直到凑足候选池。

> 本步骤可调用 `skills/news-to-broadcast/select_top.py` 自动完成打分 + 过滤，脚本会输出 top 3 到 stdout。

### Step 4：取前 3 条，AI 补全背景信息

- 取过滤后排名前 3 的资讯。
- 对每条结合 `title + desc + link`（必要时联网核实），补全：
  - 背景上下文（这件事发生在什么大趋势里）
  - 关键数字 / 人物 / 时间节点
  - 冲突点或反差点
- 背景信息只用于写稿，不直接展示给用户。

### Step 5：逐条改写 600 字口播稿

每条按「三幕结构」改写，正文严格 ≤ 600 字（中文计字，标点不计）：

- **引入（约 100 字）**：用一个反问句 / 悬念 / 具体数字钩住观众，先抛出最抓眼球的点。
- **展开（约 400 字）**：讲清「谁干了什么 / 为什么重要 / 跟你有什么关系」，穿插具体数字和画面提示词（如「PPT 切到…」）。
- **收尾（约 100 字）**：一句金句定调，留钩子引导点赞 / 关注。

### 口播稿规范

- 全文 **不超过 600 字**。
- **尽量减少英文**，必要术语首次出现给中文译名，括号注英文。
- **三幕结构**：引入悬念 → 核心展开 → 金句收尾。
- **口语化、有情绪起伏**，短句优先，念着顺嘴，避免书面长句。
- **适合真人念稿**：可配 PPT + 提示器拍摄，必要时在括号里给画面提示（如「（画面：奖励曲线飙升画面）」）。
- 不出现「本台报道」「观众朋友们」等传统播音腔，用短视频博主的语感。

## 输出格式

最终结果写入 `data/broadcast/YYYY-MM-DD.json`（项目根目录下，如已存在则覆盖）：

```json
{
  "date": "YYYY-MM-DD",
  "generated_at": "ISO8601 时间戳",
  "count": 3,
  "broadcasts": [
    {
      "rank": 1,
      "title": "原资讯标题",
      "source": "原来源",
      "link": "原链接",
      "category": "原分类",
      "score": 25,
      "score_breakdown": {
        "keyword": 9,
        "source": 5,
        "timeliness": 10,
        "topic": 8
      },
      "filter_reason": "强 AI + 名人 + 具体数字 + 直播事件，画面感强，信息密度高",
      "broadcast_script": "口播稿全文（≤600 字）"
    }
  ]
}
```

## 脚本说明

### select_top.py

选题脚本，**仅使用 Python 标准库**（`json / argparse / datetime / re / os / sys`），无第三方依赖。

- 读取 `data/news/日期.json`
- 对每条 item 计算 4 维热度指标总分
- 按 4 条筛选标准过滤
- 输出 top 3 到 stdout，格式：`标题 | 来源 | 热度分 | 筛选理由`

用法：

```bash
python3 skills/news-to-broadcast/select_top.py [YYYY-MM-DD]
```

- 不传日期时，自动读取 `data/manifest.json` 取最新一天。
- 输出末尾附 `筛选理由` 一栏，说明该条为什么能入选（命中哪些关键词 / 戏剧性元素 / 通过哪几条硬筛）。
